# Product benchmark scoreboard

Reviewed 2026-10-07 against this worktree, including uncommitted fixes. This is an evidence scoreboard, not a release certificate or a comparative speed result.

## Product thesis

Make the everyday document job feel calm and dependable: a restrained native Windows window, safe and understandable saves, measured speed, and accessibility by default. Win32, Direct2D, system themes, and local processing support this direction. They do not establish a performance or usability lead by themselves. Learn from competing workflows without copying Glance code, assets, or visual composition. Broader format coverage and AI integrations are not the differentiation or a reason to expand v1.

## How to read the scores

- **Implemented:** a working code path exists. This does not mean the complete PRD criterion passed.
- **Tested:** named automated evidence covers the stated subset. A test source alone is not a recorded pass.
- **Partial:** some required behavior or integration remains missing.
- **Blocked:** a required external dependency, device, distribution decision, or approval is outstanding.
- **Unverified:** no sufficient end-to-end evidence exists.

Several labels can apply to one row. “Lead” is a product judgment about demonstrated workflow breadth, not a timed competition. Confidence is high for inspected local code, medium for the pinned competitor teardown, and low for comparative quality or speed without a shared test.

Internal inputs: [PRD](PRD.md), [acceptance checklist](acceptance.md), [v1 plan](plan-v1.md), [benchmark method](benchmarks.md), and [Glance teardown](research/glance-teardown.md). The acceptance checklist and plan contain historical gaps that later code has partly closed. For example, the viewer sidebar and AccessKit tree now exist. Conversely, backend text, save, and export capabilities must not be counted as integrated UI workflows.

External evidence: [Glance source at the reviewed revision](https://github.com/RedtRocks/glance/tree/78e091c), with detailed source paths and prior test results in the teardown; [Apple Preview guide](https://support.apple.com/guide/preview/welcome/mac), checked on the review date. Apple's guide documents workflows, not comparable benchmarks. Glance's current public repository was checked for identity; competitor implementation claims below remain bounded to the teardown revision.

## Next product gates

1. Complete safe-save and text-selection integration before adding breadth. These determine whether users can trust the app with real documents.
2. Finish inline forms, page drag operations and export controls as coherent workflows. Engine capability alone does not finish a task.
3. Record comparable speed and memory evidence on agreed devices. Until then, say “native viewer,” not “faster than Glance.”
4. Run accessibility and independent-reader checks on the exact release build, then prove installation and removal preserve the user's Windows setup.

No GUI was launched for this scoreboard. Referenced existing test sources describe coverage; only explicitly reported focused runs above were executed during this review. This document does not change PRD scope, thresholds, or stack.
